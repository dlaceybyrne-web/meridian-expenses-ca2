# CA2 Evidence Checklist

Use this checklist while completing the practical work. Do not mark an item complete until you have produced the actual evidence.

| ID | Evidence required | Where to capture it | Status |
|---|---|---|---|
| E1 | Repository/project structure | GitHub repository | ☐ |
| E2 | GitHub Actions pipeline executing | GitHub Actions | ☐ |
| E3 | Semgrep SAST result | GitHub Actions log | ☐ |
| E4 | npm audit SCA result | GitHub Actions log | ☐ |
| E5 | Gitleaks secret detection result | GitHub Actions log | ☐ |
| E6 | Custom IDOR/BOLA test passing on secure code | GitHub Actions log | ☐ |
| E7 | Custom administrative authorisation test passing | GitHub Actions log | ☐ |
| E8 | Secure baseline pipeline passing | GitHub Actions | ☐ |
| E9 | Deliberately introduced IDOR vulnerability | Git diff / code | ☐ |
| E10 | Pipeline failure caused by custom IDOR test | GitHub Actions | ☐ |
| E11 | Restored secure IDOR implementation | Git diff / code | ☐ |
| E12 | Final successful retest | GitHub Actions | ☐ |
| E13 | Threshold/failure configuration | workflow file | ☐ |
| E14 | Standards mapping | report appendix/table | ☐ |

## Important

Do not create or edit screenshots to make a result appear successful. Screenshots should show the actual output generated by the tools and GitHub Actions.

A passing pipeline means the configured checks passed. It does not prove that the application is completely secure.
